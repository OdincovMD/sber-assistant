# Автовосстановление фоновой очереди

Celery Beat каждые пять минут проверяет транзакции со статусом `queued`.
Если задача не завершилась за `QUEUE_STALE_MINUTES`, watchdog повторно
публикует её в Redis.

Worker обрабатывает транзакцию под блокировкой строки PostgreSQL. Поэтому
watchdog использует `FOR UPDATE SKIP LOCKED` и не дублирует задачу, которая
в этот момент действительно выполняется.

После `QUEUE_RECOVERY_MAX_ATTEMPTS` неудачных восстановлений транзакция
переходит в `failed`. После устранения причины её можно снова запустить через
`POST /api/transactions/{id}/retry`; ручной запуск обнуляет автоматический
счётчик.

Переменные окружения:

- `QUEUE_STALE_MINUTES=10` — когда queued-задача считается зависшей;
- `QUEUE_RECOVERY_MAX_ATTEMPTS=3` — максимум автоматических повторов;
- `QUEUE_RECOVERY_BATCH_SIZE=100` — максимум строк за один проход.

В ответах API доступны `queued_at` и `queue_recovery_attempts`, чтобы причину
повтора можно было увидеть без доступа к БД или логам Celery.
