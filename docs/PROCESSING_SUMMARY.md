# Сводка фоновой обработки

`GET /api/transactions/summary` возвращает оперативное состояние конвейера
обработки банковских сообщений. Маршрут защищён тем же `X-API-Key`, что и
остальные `/api/*` методы.

Сводка содержит общее число транзакций, распределение по статусам, число
зависших queued-задач, число failed-задач без успешного уведомления и время
самой старой queued-записи. Все агрегаты вычисляются одним SQL-запросом.

Поле `health` принимает значения:

- `ok` — нет queued и failed операций;
- `degraded` — есть свежие queued или уже оповещённые failed операции;
- `critical` — есть зависшие queued или failed операции, уведомление о которых
  ещё не доставлено.

`rejected` считается бизнес-результатом финансовой валидации и само по себе не
ухудшает техническое состояние конвейера.

Порог зависания берётся из `QUEUE_STALE_MINUTES`. Некорректное, нулевое или
отрицательное значение безопасно заменяется на 10 минут.
