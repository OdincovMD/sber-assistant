# Liveness и readiness

`GET /health` — лёгкая liveness-проверка. Она отвечает `200`, если процесс
FastAPI работает, и не обращается к внешним сервисам.

`GET /health/ready` — readiness-проверка полного конвейера. Она параллельно
проверяет:

- PostgreSQL;
- Redis, через который API публикует Celery-задачи;
- наличие настроенной модели в Ollama.

Если все зависимости доступны, маршрут возвращает `200` и `status=ready`.
При недоступности хотя бы одной зависимости возвращается `503` и
`status=not_ready`, а поле `checks` показывает проблемный компонент.

Каждая проверка ограничена `READINESS_TIMEOUT_SECONDS` (по умолчанию 5 секунд).
Текст исключения наружу не передаётся: ответ содержит только тип ошибки.

Backend-контейнер использует лёгкую liveness-проверку, чтобы первый запуск не
заблокировал команду `make ollama-pull` до загрузки модели. Healthcheck Nginx —
внешней точки входа — использует полную readiness и становится успешным только
после готовности всего конвейера. Celery worker также ожидает healthcheck
Ollama при старте.

Маршруты `/health*` остаются публичными, чтобы Docker и внешняя система
мониторинга могли вызывать их без финансового API-ключа.
