# Пакетный retry failed-транзакций

`POST /api/transactions/retry-failed?limit=20` повторно ставит в Celery очередь
старейшие транзакции со статусом `failed`. Допустимый `limit` — от 1 до 100.
Маршрут защищён общим `X-API-Key`.

Строки выбираются через `FOR UPDATE SKIP LOCKED`, поэтому параллельные запросы
не забирают одну и ту же транзакцию. Состояние `queued` фиксируется до
публикации задач; если API аварийно завершится между commit и отправкой в
Redis, существующий watchdog позднее восстановит задачи.

Ответ содержит выбранные, успешно опубликованные и не опубликованные ID:

- `queued` — вся пачка опубликована;
- `partial` — часть публикаций не удалась и возвращена в `failed`;
- `empty` — доступных failed-транзакций нет.

Неудачная публикация не перезаписывает результат старой Celery-задачи, если та
успела завершить обработку во время пакетного retry.
